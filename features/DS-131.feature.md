# DS-131 — Fix duplicate name rejection on edit (DS-2-TC-010)

**Jira:** [DS-131](https://legionqaschool.atlassian.net/browse/DS-131) — Fix duplicate name rejection on edit (DS-2-TC-010)
**Parent:** [DS-2](https://legionqaschool.atlassian.net/browse/DS-2) — Edit existing program details
**Bug:** [DS-126](https://legionqaschool.atlassian.net/browse/DS-126) — Edit Program accepts duplicate name on save (DS-2 TC-010)

Expected result from DS-126: Save is rejected (HTTP 400/409). A visible error says the name already exists. The Edit Program modal stays open. Both programs remain listed under their original names.

---

Feature: Duplicate name rejection on Edit Program (DS-131)

# Happy paths

Scenario: A unique rename still saves
  Given I am logged in as admin
  And programs "Web Development 2026" and "Data Science Fundamentals" exist
  When I edit "Web Development 2026"
  And I change the Name to "Web Development 2026 - Updated"
  And I click Save
  Then the Edit Program modal closes
  And the program list shows "Web Development 2026 - Updated"
  And the program list no longer shows "Web Development 2026"

# Negative

Scenario: Reject an exact duplicate program name on edit
  Given a program "Web Development 2026" exists
  And a program "Data Science Fundamentals" exists
  When I edit "Web Development 2026"
  And I change the Name to "Data Science Fundamentals"
  And I click Save
  Then I see an error indicating the name already exists
  And the Edit Program modal remains open
  And "Web Development 2026" still appears in the program list
  And "Data Science Fundamentals" still appears in the program list

Scenario: A rejected duplicate edit does not remove the original program
  Given programs "Web Development 2026" and "Data Science Fundamentals" exist
  When I try to rename "Web Development 2026" to "Data Science Fundamentals"
  And Save is rejected
  Then both programs remain listed with their original names

# Edge cases

Scenario: Saving a different unique name is not treated as a duplicate of itself
  Given I am editing "Web Development 2026"
  When I change the Name to a new unique name
  And I click Save
  Then the edit succeeds

---

## Ambiguities / gaps

- DS-131 has no Gherkin in its description. Scenarios follow DS-126's expected result for DS-2-TC-010 (exact duplicate on edit).
- The demo app currently accepts duplicate names on rename. Spec marks that case with `test.fail` until DS-126 is fixed (same guardrail as DS-2 TC-007).
- Case-only duplicates are tracked by DS-129 / DS-127 and are not repeated here.
- DS-126 does not say whether a name that matches another program only after trimming leading or trailing spaces is a duplicate. That case is not automated.
