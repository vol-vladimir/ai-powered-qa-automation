# DS-129 — Fix case-only duplicate name detection on edit

**Jira:** [DS-129](https://legionqaschool.atlassian.net/browse/DS-129) — Fix case-only duplicate name detection on edit (DS-2-TC-027)  
**Bug:** [DS-127](https://legionqaschool.atlassian.net/browse/DS-127)  
**Parent story:** [DS-2](https://legionqaschool.atlassian.net/browse/DS-2) — Edit existing program details

---

Feature: Case-insensitive duplicate detection on Edit Program (DS-129)

# Happy paths

Scenario: Case-only rename to an existing program name is rejected
  Given programs "Web Development 2026" and "Data Science Fundamentals" exist
  When I edit "Web Development 2026" and change the name to "data science fundamentals"
  And I click Save
  Then I see duplicate-name validation feedback
  And the Edit Program modal remains open
  And "Web Development 2026" still appears in the program list
  And "Data Science Fundamentals" still appears in the program list

# Negative

Scenario: Case-only duplicate rename must not remove the original program from the list
  Given programs "Web Development 2026" and "Data Science Fundamentals" exist
  When I edit "Web Development 2026" and rename it to "DATA SCIENCE FUNDAMENTALS"
  Then Save is rejected
  And the program list still shows both original names

# Edge cases

Scenario: Uppercase variant of an existing name is rejected on edit
  Given a program "Web Development 2026" exists
  And a program "Data Science Fundamentals" exists
  When I edit "Web Development 2026" to "DATA SCIENCE FUNDAMENTALS"
  Then duplicate-name validation feedback is shown

Scenario: Lowercase variant of an existing name is rejected on edit
  Given a program "Web Development 2026" exists
  And a program "Data Science Fundamentals" exists
  When I edit "Web Development 2026" to "data science fundamentals"
  Then duplicate-name validation feedback is shown

## Ambiguities / gaps

- DS-129 tracks the fix; product rule is case-insensitive duplicate detection per Confluence validation rules (400/409 with visible error).
- DS-127 reports the demo app currently accepts case-only renames — spec uses `test.fail` until DS-129 fix ships.
